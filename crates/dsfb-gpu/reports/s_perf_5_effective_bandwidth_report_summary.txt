S-PERF.5 EffectiveBandwidthReport — Summary Receipt
====================================================

Panel verdict: post-S-PERF.4 panel directive (2026-05-17).
Sealed under the 10-step per-section discipline ritual.

Commit identity (panel-locked):

    S-PERF.5 computes and reports effective bandwidth for the
    Layer-A evidence factory using the S-PERF.1 traffic law,
    S-PERF.2 Layer-A boundary, S-PERF.3 public workload
    bundle, and S-PERF.4 compacted active-family plan. It
    does not claim saturation unless the measured percent-of-
    peak meets the S-PERF.1 threshold and the timing method
    is admissible.

Panel-locked one-line verdict (verbatim):

    S-PERF.4 packs the active witnesses into benchmarkable
    lanes; S-PERF.5 turns measured Layer-A bytes and time
    into an admissible bandwidth report.

Core rule:

    Effective bandwidth report != saturation claim.
    Saturation requires accounted device bytes, admissible
    CUDA timing, declared device peak bandwidth, percent-of-
    peak >= 8000 bp, and a Layer-A-only timing boundary.

----------------------------------------------------------------
Court-delta posture
----------------------------------------------------------------

S-PERF.5 ships ONLY the report schema + verifier + builder +
uninstrumented baseline + renderers + CLI subcommands.

  - LayerABandwidthMeasurementV1
    Raw measurement: device traffic receipt hash (citation
    to S-PERF.1), device identity, theoretical peak GB/s,
    measured kernel time in microseconds, timing method
    wire name, total accounted device bytes, computed
    effective bandwidth in GB/s, computed percent-of-peak
    in basis points, plus the LayerA forbidden-flag mirror
    (host_json / casefile_materialization / host_transcript
    presence flags — all must be false).

  - BandwidthClaimAdmissionV1
    Verdict record: claim_kind (NoClaim / EffectiveBandwidth
    / PercentOfPeak / Saturation), panel-locked admissibility
    reason wire name, admitted boolean.

  - EffectiveBandwidthReportV1
    Top-level META-hash envelope binding the measurement +
    admission + four upstream anchor hashes (S-PERF.1
    DeviceTrafficReceipt + S-PERF.2 LayerATrafficReceipt +
    S-PERF.3 PublicDataSaturationBundle + S-PERF.4
    FamilyCompactionBenchmarkSchema).

  - BandwidthClaimKind (enum, 4 variants):
    NoClaim, EffectiveBandwidth, PercentOfPeak, Saturation.
    Wire names stable for the hash buffer.

  - 4 panel-locked admissibility-reason wire-name constants:
      AdmissibleNoClaim
      AdmissibleEffectiveBandwidthBackedByByteAccounting
      AdmissiblePercentOfPeakWithDeclaredDeviceBandwidth
      AdmissibleSaturationWithCudaEventTimingAndFullReceiptChain

Forbidden benchmark-claim substring scanner
----------------------------------------------------------------

The case-insensitive scanner enforces a 12-entry set
(verbatim mirror of S-PERF.3 / S-PERF.4):

  achieves saturation
  saturates the bandwidth
  saturates peak
  % of peak
  percent of peak
  outperforms
  beats the baseline
  world record
  fastest gpu
  production-ready performance
  petaflops
  memory-bandwidth saturation

Applied to: report_id, admissibility_reason_wire_name.

These are CLAIMS, not measurements. They belong in the
structured claim_kind + admitted fields, not in free-text
flourishes.

----------------------------------------------------------------
Panel-locked non-claims
----------------------------------------------------------------

S-PERF.5 does NOT:

  - claim memory-bandwidth saturation at baseline (baseline
    report is BandwidthClaimKind::NoClaim);
  - run any benchmark itself;
  - change any CUDA kernel;
  - change any court decision (S1.3a / FF.2 / FF.3 / S1.3d /
    S1.3e / S1.3f / S1.3g);
  - mutate any upstream hash anchor (corpus_hash_v1,
    corpus_hash_v2, every T.11.x / T.12.x / FF.x / S1.3.x /
    T.12.PROV / S-PERF.1 / S-PERF.2 / S-PERF.3 / S-PERF.4
    hash byte-identical);
  - alter SEED.len() (stays at 54);
  - emit detector outputs / witness records / fusion tensors
    / candidate intervals / episodes;
  - decide contraindications or challenges;
  - modify the registry crate;
  - download or fetch any dataset bytes.

S-PERF.5 ships the verdict layer; later S-PERF.* commits
populate measured fields and turn the NoClaim baseline into
measured saturation reports.
