S-PERF.7 --- source-report import verifier (summary)
=====================================================

Campaign identity
-----------------

S-PERF.7 is the first Track B leg. It makes the S-PERF.6
measurement chain mechanically empirical: the corpus crate
now PARSES the on-disk bench source reports and rejects any
drift between the parsed values and the panel-pinned
S-PERF.6 receipt constants. The corpus crate remains
panel-locked host-only with zero CUDA dependency; the
parser walks bytes; the verifier asserts equality.

Without S-PERF.7 a hand-edit of the S_PERF_6_* const prefix
in the corpus crate could silently drift from disk and pass
every existing test. S-PERF.7 closes that loop.

What this DOES
--------------

  - Parses reports/d64_stage_timing_256x4096_K1.txt into a
    typed ParsedD64StageTimingV1 struct (host wall median,
    device total, consensus_grid_kernel_wide, tree_digest
    consensus, both host segments, measured wide bandwidth
    in centi-GB/s, episode_count at 256x4096 K=1).
  - Parses reports/r12_d64_saturation.txt into a typed
    ParsedR12bSaturationV1 struct carrying the three K=1
    episode pins (canonical 13 / mid 89 / full 1917).
  - Builds a hashable SourceReportImportVerifierReportV1
    envelope binding both parsed reports + the live
    S-PERF.6 baseline report hash + verifier provenance.
  - verify_source_reports_match_s_perf_6_baseline(...)
    rejects any drift via four panel-required load-bearing
    negatives plus structural rules.

What this DOES NOT do
---------------------

  - Does NOT run the bench (corpus crate is host-only).
  - Does NOT rewrite source reports.
  - Does NOT mutate the S-PERF.6 receipt or any prior hash
    anchor.
  - Does NOT alter SEED.len().
  - Does NOT rebaseline R.12b.
  - Does NOT change measured bandwidth (no kernel changes).

Parser strictness
-----------------

The bandwidth-line grammar accepts X.YY GB/s with EXACTLY
two decimal digits. 7.7 GB/s is rejected as malformed so
silent rounding cannot disguise a precision drop. The
R.12b parser ignores wall-time columns (which drift
run-to-run with thermal load) and reads only the K=1
episode-count rows; pinning wall-time would force a
rebaseline on every bench rerun, which is exactly the
panel-forbidden anti-pattern.

Track B linkage
---------------

S-PERF.7 does NOT change measured bandwidth (no kernel
changes). It strengthens the measurement chain so
subsequent Track B legs can ratchet the live measurement
upward with the receipt automatically tracking the bench
output rather than drifting silently.
