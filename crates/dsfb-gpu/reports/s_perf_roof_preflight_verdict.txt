----------------------------------------------------------------
 Override of the earlier-default S-PERF.14 design
----------------------------------------------------------------

The S-PERF.13 plan + memory carried a panel-suggested default
S-PERF.14 lever of "fuse the 4 compact_densor digest stages".
That suggestion was based on the LOGICAL `wide bytes/sec`
metric (264 B/cell x cells/sec) which does NOT measure
physical fabric traffic.

ROOF-PREFLIGHT measured the ACTUAL device-fabric distribution
and found the dominant actionable bucket is OCCUPANCY-BOUND,
not L2-bound. The single largest offender (drift_slew_sign_kernel)
is also NOT a compact_densor stage. Five kernels expose only
~8 blocks to an 80-SM RTX 4080 SUPER; ncu reports "The grid for
this launch is configured to execute only 8 blocks, which is
less than the 80 multiprocessors used."

S-PERF.14 is therefore RETARGETED to launch-geometry repair
for per-entity-serial kernels. Digest fusion is deferred to a
later S-PERF.x once launch-geometry repair lands and the next
ROOF measurement shows L2 (not occupancy) as the dominant
bucket.

----------------------------------------------------------------
 Recommended S-PERF.14 sequence (panel-locked)
----------------------------------------------------------------

  1. Fix drift_slew_sign_kernel first (largest single-kernel
     wall at 1.6 ms / 2.1% occupancy).
  2. Expand grid geometry from per-entity serial shape to
     tiled cell/window work.
  3. Preserve deterministic indexed output slots via a thin
     Pre-Alpha entity-serial precompute kernel for the EWMA
     carry (matches the S-PERF.11 + S-PERF.12a discipline).
  4. No completion-order merge; output bytes MUST be byte-
     identical to the pre-S-PERF.14 path; episodes 13/89/1917
     byte-stable.
  5. Re-run S-PERF.ROOF-PREFLIGHT after the launch-geometry
     fix to verify the dominant bucket shifted.
  6. Only then revisit digest fusion if compact_densor stages
     remain dominant.
