Per-passport operational fields (panel-locked schema)
----------------------------------------------------------------

Each T12RatifiedPassport carries:

  canonical_id                : u32 in 5001..=6699
  display_name                : from originating ProposedPrimitive
  source_class_wire_name      : from origin proposal
  origin_proposal_id          : e.g. t12_p_information_theory_first_proposal
  gpu_family_wire_name        : derived via source_class_to_gpu_family
                                 (panel-locked SourceClass->GpuFamilyKernel)
  activation_applicability_tags: derived via source_class_to_activation_tags
                                 (panel-locked SourceClass->tag-set)
  contraindication_linkage_stub: ContraindicationStub { declared=true, linked=[] }
  challenge_surface_stub      : ChallengeStub { declared=true, linked=[] }
  passport_hash_v1            : per-passport SHA-256 under the FF.1
                                 T.12-ratified-passport domain separator

The contraindication + challenge stubs are panel-locked at
empty-but-declared at FF.1 time. Later FF.1.x or post-FF.3
commits populate them via the T.11g ContraindicationReceipt
+ T.11f ChallengeDocketV1 crosswalks. FF.1 reserves the field
shape so the per-passport hash binds the stub presence even
when the stub is empty.

----------------------------------------------------------------
Panel-locked non-claims
----------------------------------------------------------------

FF.1 does NOT:

  - Reopen T.12 dedup decisions. The expansion index is
    consumed read-only.
  - Add new literature primitives. Every passport materialised
    refers to a canonical id already in the T.12 expansion
    index (5001..=6699 reserved bands).
  - Alter corpus_hash_v1 (stays at 35c276c7...).
  - Alter corpus_hash_v2 (stays at f1d132eb...).
  - Rewrite any historical T.12 proposal / batch / dedup-delta
    hash.
  - Rewrite any T.12.consolidate hash (consolidation_report
    _hash_v1, t12_expansion_index_hash_v1, corpus_hash_v2).
  - Mutate SEED.len() (stays at 54).
  - Activate any detector. Activation is S1.3a's job; FF.1
    only materialises the passport so the activation planner
    has a target to read.
  - Decide contraindications or challenges. The stub fields
    reserve the space; population is a later commit.
  - Generate CUDA kernels. The GPU family mapping is a
    declaration of which family the passport would route to;
    kernel generation is a much later commit.
