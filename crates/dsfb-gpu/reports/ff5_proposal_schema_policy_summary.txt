================================================================
FF.5 - ProposalSchemaUpgradePolicy
       summary receipt
================================================================

Panel-locked opening guard. FF.5 defines how proposal schema
upgrades are allowed to re-render historical proposal artifacts
without erasing the old artifact hashes or confusing the court
lineage. Core rule: schema upgrade != silent artifact rewrite.
Required doctrine: if a schema change re-renders old proposals,
the migration must preserve the old artifact hash, emit the new
schema hash, explain why the rendered bytes changed, and provide
an explicit old_hash -> new_hash migration table. The old
artifact remains part of the evidence trail; the new artifact
becomes the active schema rendering only through an explicit
migration receipt.

Panel-locked one-line verdict (verbatim):

> Schema upgrade != silent artifact rewrite.

Why this is forward-looking: the post-T.12.consolidate /
post-FF.1 / post-FF.2 / post-FF.3 / post-FF.4 arc surfaced
several future-work items (e.g. richer ProposedSourceRef with
authors / doi_or_url, structured contract flags on
ProposedPrimitive, ratification_commit split) that will
eventually require re-rendering historical T.12.x proposal
artifacts under a v2 schema. FF.5 lands the policy BEFORE any
schema upgrade so every future upgrade has a known contract
to satisfy.

----------------------------------------------------------------
Policy doctrine (10 panel-locked lines, pinned verbatim)
----------------------------------------------------------------

  1. Schema upgrade != silent artifact rewrite.
  2. Historical proposal artifacts are court evidence.
  3. A schema upgrade may produce new rendered artifacts, but
     it must not pretend the old bytes never existed.
  4. Every schema-driven re-render must preserve the archived
     old hash, emit the new schema/version hash, explain the
     semantic reason for the byte change, and record a
     migration table from old hash to new hash.
  5. The old artifact remains part of the evidence trail; the
     new artifact becomes the active schema rendering only
     through an explicit migration receipt.
  6. corpus_hash_v1 is the historical seed-corpus anchor
     frozen at T.10; no schema upgrade may mutate it.
  7. corpus_hash_v2 is the ratified-corpus authority anchor;
     any schema upgrade that mutates it requires a declared
     freeze campaign id.
  8. Every migration row must declare a non-zero
     old_artifact_hash, a non-zero new_artifact_hash, the old
     schema version, the new schema version, the
     old_artifact_id, and the semantic reason the bytes
     changed.
  9. Migration table rows have unique old_artifact_hash
     values and unique new_artifact_hash values across the
     whole table.
 10. Every receipt must declare the old artifact hash was
     VALID at filing time; a migration is not a correction.
