Section 1 — Field change on `DetectorSpec`
================================================================

  pub source_corpus_hash: [u8; 32]

  Lives between `corpus_binding_status` and `canonical_name`.
  Carries the corpus_hash_v1 bytes for HashFrozenT10 specs;
  MUST be the all-zero sentinel for PreHashT9InternalAudit
  specs. The verifier enforces this cross-field rule.

Section 2 — Verifier surface
================================================================

  verify_spec (base) — enforces:
    SpecMissingParameterHash      parameter_hash == [0; 32]
    SpecHashFrozenWithoutT10      cross-field rule violation
                                  (both directions; the variant
                                  kind name is preserved from
                                  the original S1.1 gate)
    EmptyAxisBinding              axis_binding is empty
    EmptyDomainTagSet             domain_tags is empty
    InvalidWindowCells            window.cells == 0
    InvalidPersistenceWindows     persistence_windows == 0
    CanonicalNameWrongTokenCount  canonical_name not 6 tokens
    CanonicalNameHasEmptyToken    canonical_name has empty token

  verify_registry_spec (S1.2+ callers) — additionally enforces:
    SpecMustBeHashFrozenAtS12     status != HashFrozenT10
    SpecSourceCorpusHashStale     source_corpus_hash != expected
    SpecPrimitiveIdUnknown        primitive_id absent OR not in
                                  corpus canonical-id set

  Signature:
    pub fn verify_registry_spec(
        spec: &DetectorSpec,
        expected_corpus_hash: &[u8; 32],
        corpus_canonical_ids: &[DetectorCanonicalId],
    ) -> Vec<VerifyError>

  The registry verifier takes the expected corpus hash + the
  admissible canonical-id set as parameters so the registry
  crate stays free of hard-coded corpus snapshots. The caller
  pulls them from the corpus crate's
  `compute_corpus_hash_v1()` and `SEED`.
