S1.3f CaseFileV2 Activation Integration — Summary Receipt
===========================================================

Panel verdict: post-S1.3e panel directive (2026-05-17). Sealed
under the 10-step per-section discipline ritual.

Commit identity (panel-locked):

    S1.3f binds activation, context, budget pruning,
    redundancy suppression, and KernelPlanV1 into CaseFileV2
    so every emitted case file carries the court authority
    chain that determined which witnesses were eligible,
    activated, budget-admitted, packed into kernel lanes, or
    suppressed.

Panel-locked verdict (verbatim):

    S1.3f makes CaseFileV2 carry the whole activation-to-
    kernel authority chain, so evidence output cannot be
    detached from the court decisions that allowed it to
    exist.

Core rule:

    A case file must not contain witness/candidate results
    without the activation and kernel-plan authority chain
    that made those witnesses admissible to run.

----------------------------------------------------------------
Court-delta posture
----------------------------------------------------------------

S1.3f produces three case-file sections plus three META-hashes
that bind every upstream court anchor into a replayable
authority chain:

  1. Activation binding — META-hashes the six activation-side
     anchors:
       * S1.3a activation_plan_hash_v1
       * S1.3b activation_decision_transcript_root_hash_v1
         (root over every per-detector transcript hash, sorted
         ascending by canonical id)
       * S1.3c activation_context_hash_v1
       * S1.3d budget_pruning_plan_hash_v1
       * S1.3d redundancy_suppression_hash_v1
       * S1.3d budgeted_activation_summary_hash_v1

  2. Kernel-plan binding — META-hashes the three S1.3e
     anchors plus a per-detector lane membership index:
       * S1.3e kernel_plan_hash_v1
       * S1.3e kernel_family_schedule_hash_v1
       * S1.3e kernel_parameter_table_hash_v1
       * lane_membership_index: 152 rows, each mapping an
         Active canonical id to a (gpu_family_wire_name,
         lane_offset) pair, sorted ascending by canonical id.

  3. Authority chain (top-level) — META-hashes the two
     bindings above plus FF.2 + FF.3 gate hashes + the T.11g
     contraindication snapshot hash + the T.11f challenge
     docket snapshot hash + the T.11h coverage-hole snapshot
     hash + corpus_hash_v1 + corpus_hash_v2.

The reason-code separation continues: S1.3f does NOT mutate
or re-decide any upstream record. It links them into a single
hash so a future CaseFileV2 body populator cannot detach
witness/candidate results from the chain that made them
admissible.

----------------------------------------------------------------
Panel-locked non-claims (must appear in README + paper + plan)
----------------------------------------------------------------

S1.3f does NOT:

  - emit detector outputs, witness records, fusion tensors,
    candidate intervals, episodes, or any other body-of-
    evidence field;
  - execute kernels (S1.3e already barred that);
  - mutate any upstream hash anchor (S1.3a / S1.3b / S1.3c /
    S1.3d / S1.3e / FF.x / corpus_hash_v1 / corpus_hash_v2
    are all read-only);
  - alter SEED.len() (stays at 54);
  - change S1.3a / FF.2 / FF.3 / S1.3d / S1.3e court
    decisions;
  - generate CUDA kernels;
  - decide contraindications or challenges (it only links
    them);
  - modify the registry crate.

S1.3f is the linkage layer that turns the activation +
kernel-plan court into a single replayable authority chain
the future CaseFileV2 body populator MUST cite.
