------------------------------------------------------------------------
 v2 design (panel-locked direction; what was rebuilt + why)
------------------------------------------------------------------------

v1 failure mode (diagnosed in step0_baseline.txt): the 1-thread
streaming root kernel eliminated Path 1a's scratch round-trip
but ALSO eliminated Path 1a's 256-thread cooperative byte-load
parallelism, producing a 3.09× per-kernel regression
(925 → 2860 µs).

v2 design preserves BOTH properties:

  Phase 1 (thread 0 only)
    Build 44-byte canonical header in registers, stream into
    per-thread SHA-256 context. ZERO global writes.

  Phase 2 (block-cooperative tiled loop; TILE_BYTES = 2 048)
    for each tile (32 SHA blocks per tile = 2 048 bytes):
      - 256 threads cooperatively load the tile from global
        d_compact_densor_leaves into dynamic shared memory.
        Byte-granular cooperative copy (avoids the
        uchar4 / uint4 misaligned-load trap S-PERF.14b
        documented).
      - __syncthreads().
      - Thread 0 calls dsfb_sha256_update(&ctx, shared_tile, tile_len)
        — streams the shared-resident tile through the SHA-256
        state with the aligned-bulk fast path landing on
        complete 64-byte blocks directly out of shared memory
        (no per-byte copy into ctx->buf for full blocks).
      - __syncthreads().

  Phase 3 (thread 0 only)
    Finalise SHA state and write 32-byte root to canonical
    catalog-indexed output slot.

Wins preserved:
  - Path 1a's 256-thread cooperative byte movement (Phase 2 load).
  - Path 1a's serial SHA correctness (thread 0 finalises).
  - Path 1a's byte-identical CompactDensorDigestV1 contract
    (same domain || header || canonical-ordered leaves byte stream).

Wins added:
  - Zero global scratch allocation needed for the digest path.
  - Reads come from 1-cycle shared memory, not L2-resident
    global scratch.
  - Block achieves 16.6 % occupancy (vs Path 1a's 2.7 %).

Streaming-SHA-update fast-path (load-bearing micro-optimisation):
the per-tile invocation now compresses 31 of the 32 64-byte
blocks DIRECTLY from the shared-memory pointer (when
ctx->buf_len == 0 AND ≥ 64 bytes remain), only staging the
44-byte tail into ctx->buf. Byte-identical to the slow path —
proven by the dsfb_gpu_sha256_streaming_self_test known-vector
harness (empty / 55 B / 64 KiB inputs cross-validated against
one-shot dsfb_sha256_device AND host SHA-256).

------------------------------------------------------------------------
 Honest mixed verdict (panel-locked framing)
------------------------------------------------------------------------

The per-kernel ROOF measurement is the load-bearing court witness
(per the panel-locked rule "bench is noise filter, ncu is verdict"):

  Δ per-call wall          : 925.2 → 1,008.4 µs   (+9.0 % SLOWER)
  Δ occupancy              :   2.70 → 16.62 %     (+13.92 pp / 6.2×)
  Δ DRAM throughput        :   0.70 → 0.31 %      (scratch round-trip
                                                   eliminated, as designed)
  Δ L1/TEX throughput      :   4.90 → 4.81 %      (~unchanged)
  Δ L2 throughput          :   0.21 → 0.21 %      (unchanged)

The +9 % per-kernel regression originates in the streaming-SHA
+ per-tile-sync overhead being slightly higher than Path 1a's
one-shot SHA over the entire L2-resident scratch concatenation.
Even with the aligned-bulk fast path, the per-tile loop incurs
two extra __syncthreads() per tile plus the SHA staging-buffer
maintenance at tile boundaries.

The 6.2× occupancy improvement is a structural quality win: the
block runs many active warps during Phase 2's cooperative
cooperative load even though Phase 3 (thread-0 finalise) is
serial. Path 1a's 2.7 % occupancy was the structural K=1 floor;
v2 lifts that to 16.6 % without changing the K=1 contract.

System bench steady-state is +8.1 % above PRE median, but the
8-run band width (16.56 → 25.47 GB/s, ~9 GB/s spread =
~3.8 ms / dispatch spread) means the ~0.9 ms / dispatch
steady-state delta sits inside the run-to-run thermal noise
of Path 1a. System bench is REPORTABLE-COMPARABLE, not a
decisive win.

This is **not a measured per-kernel acceleration**. It is a
**structural cleanup**: eliminated dependency on global scratch
arena for the digest path; cleaner kernel topology;
6.2× occupancy lift; streaming SHA primitives validated and
shipped as building blocks.

User-stated tier (verbatim 2026-05-18 v2 spec):
  "If v2 lands at: 925 µs → 750–850 µs that is a valid win.
   If v2 lands at: 925 µs → 500–700 µs that is a serious
   root-path breakthrough."
We landed at 925 → 1,008 µs. **Below the tier-1 valid-win bar.**

------------------------------------------------------------------------
 Why NOT revert (panel verdict; load-bearing rationale)
------------------------------------------------------------------------

Per user's explicit rejection of the v1 revert ("no reverting
was lazy ... reject the 'revert and close' instinct"), v2 ships
as a structural-cleanup commit rather than a revert-to-Path-1a:

  1. The streaming SHA primitives in cuda/sha256.cuh
     (dsfb_sha256_init / _update / _finalize) are validated
     building blocks. Byte-identical to one-shot SHA on every
     known-vector test. They unlock future digest-path designs
     that can't be expressed cleanly with one-shot SHA over a
     materialised buffer (e.g., interleaved evidence streaming
     during fused kernels).

  2. The block-cooperative shared-memory tile pattern is a
     structurally cleaner organisation than global-scratch
     round-trip. The compact_densor digest path no longer needs
     to ensure a per-stage scratch buffer in workspace; the
     dynamic-shared-memory allocation is per-launch.

  3. The aligned-bulk fast path in dsfb_sha256_update is a
     general-purpose optimisation that benefits any future
     streaming-SHA caller (not just the root kernel) — every
     full 64-byte block compresses directly from the source
     pointer without per-byte staging.

  4. Byte-identity holds across the full Track B chain (5/5
     14b.1 pins + 83/83 cross-validation tests). The
     CompactDensorDigestV1 contract is preserved exactly.

  5. R.12b episodes 13/89/1917 byte-stable; pinned R.12b
     baselines restored from HEAD pre-commit; D128/D205
     dispatchers untouched (legacy Path 1a root kernel
     remains in source as documented fallback).

  6. The +9 % per-kernel regression is small in absolute
     terms (+83 µs / call × 4 calls / dispatch = +332 µs /
     dispatch); the system-level bench shows it disappears
     into thermal noise. A revert would lose the structural
     cleanup AND the streaming primitives AND the fast-path
     optimisation for no measured win.

------------------------------------------------------------------------
 Lesson for next campaign (panel-recorded)
------------------------------------------------------------------------

The compact_densor_root layer's per-call wall is dominated by
the serial SHA compute floor (thread 0 driving the entire
SHA-256 stream). Path 1a and Path 1b v2 both pay that floor
because both run one SHA per catalog on one thread. The
remaining levers are:

  a) Parallel SHA at the kernel level (would change byte stream
     → CompactDensorDigestV2; PANEL-FORBIDDEN under digest-mode
     non-aliasing law).

  b) Move the compact_densor work into the leaf-kernel cooperative
     fold so the root reduction becomes much smaller (a different
     algorithmic decomposition; would change byte stream → V2).

  c) Larger remaining device wall lives in memory-bound kernels:
     detector_motif_fused 1.32 ms @ 91 % L2 + consensus_axis5_fused
     400 µs @ 88 % L2. Those are ~2× more cumulative wall than the
     root kernel and are amenable to memory-pattern optimisation
     within the existing contract.

Recommendation: next S-PERF.x sub-leg should target those
memory-bound kernels (per-kernel ncu measurement first); the
compact_densor_root layer is at its structural floor under the
v1 digest contract.
