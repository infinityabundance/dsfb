=== Trajectory across the S-PERF.12 design pass ===

The panel-locked S-PERF.12 thesis (XOR-fold compact projection beats
SHA-256 streaming at the canonical chunk geometry) was tested by two
sequential implementations during this design pass:

--- Variant 1: naive per-thread chunk fold (REJECTED) ---

Geometry  : one thread per chunk; LEAVES_PER_BLOCK = 32 (mirroring
            S-PERF.11 tree_digest_leaf_kernel_v2).
Algorithm : each thread reads its own 16,384-byte chunk byte-by-byte
            and XOR-folds into a per-thread 64-byte compact slot in
            dynamic shared memory; thread 0 SHA-256s the slot.

Measured  : wide bytes/sec 8.81 / 9.39 GB/s (2 runs, 3-iter median);
            a ~42% REGRESSION vs S-PERF.11's pinned 16.38 GB/s.
            Digest total rose from 8,556 us to 16,092 us.
            R.12b episodes 1917 byte-stable; no CUDA 700;
            non-aliasing law satisfied. Failed both
            "beats S-PERF.11" and ">20 GB/s minimum useful" gates.

Root cause: uncoalesced global-memory reads. With 32 threads in a warp
            each reading bytes from chunks 16,384 bytes apart, every
            byte read fetches a separate cache line — 32 transactions
            per byte vs 1 transaction per 32 bytes for coalesced
            access. The XOR-fold's added per-thread work (16,384
            reads + 16,384 XORs per chunk) exceeded the SHA-256
            savings (256 compress blocks -> 1).

Status    : Rejected. Not shipped. Carried in this receipt as a
            panel-recorded failed-implementation witness.

--- Variant 2: warp-cooperative coalesced fold (S-PERF.12a) ---

Geometry  : one warp (32 threads) per chunk; block dim
            (WARP_SIZE=32, WARPS_PER_BLOCK=16, 1). Grid
            (ceil(n_chunks / 16), 1, n_catalogs).

Algorithm :
  * Phase 0: each lane zeros its own 64-byte private accumulator slot
    inside dynamic shared memory.
  * Phase 1: 512 waves at chunk_size=16384. In wave w, lane t reads
    chunk_ptr[w*32 + t] — COALESCED across the warp (one 128-byte
    cache line per wave). The byte maps to compact index
    (w*32 + t) / 256; with FOLD=256, every 32-byte wave fits in
    ONE compact byte. Each lane XORs its byte into its own private
    accumulator — no atomics, no shuffles, no cross-lane contention.
  * Phase 2: parallel cross-lane reduction. Two passes of 32 lanes
    each cover the 64 compact bytes. Each lane reads 32 source bytes
    (one per lane's accumulator) and XORs them into its compact byte.
    No shuffles, no atomics; XOR is order-independent.
  * Phase 3: lane 0 SHA-256s the 64-byte compact slot into the
    per-chunk leaf digest. Other lanes idle.

Per-warp dynamic shared memory:
    32 lanes x 64 bytes (lane locals) + 64 bytes (compact slot)
    = 2112 bytes.
Per-block: 16 x 2112 = 33,792 bytes (within 48 KiB default sm_89
    limit; no opt-in needed).

Measured  : steady-state median 18.72 GB/s across 5 runs (cold-start
            outlier 12.78 excluded). Detail: 17.57 / 18.81 / 18.66
            (restoration verification, 3 runs) plus 18.48 / 18.60 /
            18.84 / 18.86 / 18.86 (initial 5-run stability check).

Status    : PARTIAL SUCCESS. Beats S-PERF.11 (+14.3%); reduces
            digest_total by ~26%; fully correct; satisfies every
            S-PERF.12 gate EXCEPT the >20 GB/s minimum useful gate.
            Recorded as S-PERF.12a candidate, NOT sealed as full
            S-PERF.12 completion.

=== Structural diagnosis: why 20 GB/s requires S-PERF.13, not more digest work ===

Full-scale stage breakdown at WPB=16, post-warm-up median:

  h2d (WindowFeature[] H2D)             2.5 ms
  host compute_features                 7.1 ms   <- dominant wall (S-PERF.13 lever)
  detector_motif_kernel_wide_d64        2.7 ms
  4x compact_densor digest stages       6.3 ms   <- S-PERF.12a reduction
  drift_slew_sign / consensus /
    candidate_collapse / axis5_grid     2.7 ms
  host bank admit + case finalize       2.2 ms
                                       ------
  total host wall                      ~23.5 ms  ->  18.72 GB/s

A hypothetical zero-cost digest (digest_total -> 0) would bring wall
to ~17.2 ms = ~25.6 GB/s. S-PERF.12a already extracted ~26% of
digest cost (8.6 -> 6.3 ms = -2.3 ms), which is most of the
digest-side headroom available at this geometry. Further digest
optimization yields diminishing returns.

The dominant non-digest wall segment is host compute_features at
~7.1 ms. Eliminating it (replacing with a device-side
deterministic kernel under S-PERF.13) alone brings wall to
~16.4 ms = ~26.8 GB/s, clearing the >20 GB/s gate without
touching the digest path. S-PERF.13 is the panel-locked next
strike (gate-3 lever per the saturation ladder).

After S-PERF.13 lands, S-PERF.12a's infrastructure can be
re-measured against the new post-S-PERF.13 stage breakdown; if
digest still represents a measurable share of device_total, the
S-PERF.12a warp-cooperative kernel can be re-evaluated against a
revised completion gate.
