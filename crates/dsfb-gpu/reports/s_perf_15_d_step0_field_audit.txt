 DetectorCellWide field-consumption audit

DetectorCellWide layout (crates/dsfb-gpu-debug-core/src/detector.rs:181):
  pub struct DetectorCellWide {                       byte range
      pub window_idx: u32,                            [ 0 ..  4)    4 B
      pub entity_id:  u32,                            [ 4 ..  8)    4 B
      pub detector_mask: DetectorMask2048,            [ 8 .. 264)  256 B
  }                                                   total       264 B

DetectorMask2048 = [u64; 32]. At D64, only mask[0] is populated
(64 active detectors live in bits 0..63 of mask[0]); mask[1..31]
are written to zero by the detector_motif_fused_d64_kernel for
every cell.

Important observations:

  - At D64, ONLY mask[0] (8 B / 264 B = 3.0 % of the cell) is hot.
    97 % of every cell write is zero bytes.
  - window_idx + entity_id are NEVER read by any downstream stage
    on the throughput path. Consumers derive these values from
    CUDA blockIdx (entity_id = blockIdx.y; window_idx = blockIdx.x
    or threadIdx.x). They are written but never read.
  - The legacy detector_wide_digest_pack_kernel_v1 (D128/D205
    path) reads only mask[0] at D64. Even the legacy unfused 2-
    kernel pair never reads mask[1..31] at D64.

------------------------------------------------------------------------
 Per-cell footprint summary at canonical 256x4096 K=1
------------------------------------------------------------------------

WRITE side (detector_motif_fused_d64_kernel):
  cells per dispatch          = 256 entities × 4 096 windows = 1 048 576
  bytes written per cell      = 264 B (full DetectorCellWide store)
  TOTAL write traffic         = ~277 MB
  of which:
    hot bytes (mask[0] only)  = 1 048 576 × 8 B = 8 MB     (3 %)
    cold zero bytes           = 1 048 576 × 256 B = 269 MB (97 %)

READ side (consensus_axis5_fused_kernel):
  per cell, reads:
    1 self-cell                    via project_d64_to_u16(det)
    TEMPORAL_WINDOW=32 neighbor cells via project_d64_to_u16(det)
    = 33 cell reads per (entity, window)
  Effective bytes per cell read:
    - if compiler loads only mask[0]:   33 × 8 B  =   264 B per cell
    - if compiler loads full 264 B:     33 × 264  = 8 712 B per cell
  At 1 M cells:
    - best case (only mask[0]):    8 GB total
    - worst case (full struct):  272 GB total
  Reality: CUDA loads via `const DetectorCellWide&` typically
  result in 128-byte cache-line fills × however many lines the
  struct spans. The 264 B struct spans 3 cache lines (128 + 128
  + 8 padding). So the compiler likely fetches 3 cache lines per
  cell access = 384 B / cell. At 33 × 1 M = 33 M cell accesses =
  ~12.6 GB of L2/DRAM read traffic.

READ side (candidate_pack_kernel_wide_blockcoop):
  per (slot, entity, catalog) block walks per-slot window range;
  reads 1 detector cell per window via project_d64_to_u16(det)
  Cell-reads scale with sum of (end_w − start_w) over admitted
  candidates; much smaller than consensus's 33×1M.

Aggregate L2 pressure on detector_motif_fused (post-S-PERF.15.c ROOF):
  detector_motif_fused itself: 2.49 ms @ 91.9 % L2.
  The 91.9 % L2 is the WRITE-allocate cost of the 277 MB wide-
  arena store. mask[1..31] zero writes account for 269 MB / 277 MB
  ≈ 97 % of the write payload; only 8 MB carry meaning at D64.

Interpretation:

  - DRAM is 8.7× write-dominant. The 420 MB DRAM write payload
    ≈ 277 MB wide-arena store (264 B × 1 048 576 cells)
    + 18 MB compact-pack store + ~125 MB write-allocate
    amplification. Of the 277 MB wide-arena bytes, the field
    audit predicts 269 MB (97 %) is cold mask[1..31] zero
    writes that no downstream stage consumes at D64.
  - L1 LD bytes are large (2.18 GB) but ~95 % of those LDs
    are served by L1/L2 cache (DRAM read is only 48 MB → ~22×
    L1 amplification). The READ side is essentially free
    compared to the WRITE side; loads come from constant-
    memory thresholds + residual/sign cells that fit in L1.
  - L2 write sectors > L2 read sectors → L2 is acting as a
    write-buffer for the DRAM-write payload (L1 ST drains to
    L2 then drains to DRAM with ~5× compression — the cold-
    zero bytes compress well in transit, but DRAM still pays
    the bandwidth).

   write-dominant. Direction A or C is justified. Specifically,
   sectors_ST / sectors_LD > 5 strongly favors A/C."

  Measured at DRAM:    ST/LD bytes = 8.71×  (>>>> 5)
  Measured at L2:      ST/LD sect  = 1.39×  (write-heavy)

  → Direction C (hybrid) is only justified if B's read-side
    win on consensus is needed; the byte-counter trace says

------------------------------------------------------------------------
 Recommended Step 1 direction (post-byte-counter; awaiting panel verdict)
------------------------------------------------------------------------

DIRECTION A — D64 conditional-write (cold-zero skip on mask[1..31])

Mechanism: detector_motif_fused_d64_kernel's Phase 2 wide-cell
store currently writes the full 264 B `DetectorCellWide` per cell
including 256 B of `detector_mask[0..31]` (of which only mask[0]
carries meaning at D64). The rewrite skips the cold tail writes
mask[1..31] entirely on the D64 _timed path:

  Before:  detectors_wide[idx] = cell;        // 264 B write
  After:   detectors_wide[idx].window_idx     = cell.window_idx;  // 4 B
           detectors_wide[idx].entity_id      = cell.entity_id;   // 4 B
           detectors_wide[idx].detector_mask[0] = cell.detector_mask[0]; // 8 B
           // mask[1..31] DELIBERATELY NOT WRITTEN at D64

  Total wide-arena write traffic: 264 B → 16 B per cell (16.5× cut)
  Total DRAM-write payload:       420 MB → ~160 MB (2.6× cut)
  Projected L2 % on detector_motif_fused: 92.3 % → 50-60 % (estimated)

Pre-condition for byte-identity contract preservation:
  - The wide arena's mask[1..31] bytes are GARBAGE post-rewrite
    (they retain whatever was there from a prior dispatch OR
    are zero if the workspace buffer was newly allocated).
  - PINNED_PRE_S_PERF_15_D_DETECTOR_CELLWIDE_ARENA_SHA256
    (pin #1) will FIRE on the post-rewrite codebase because
    the mask[1..31] bytes are no longer guaranteed zero.
  - REQUIRED panel verdict: accept the divergence under a
    "D64 path defines its own write contract: the bytes
    mask[1..31] are non-load-bearing at D64; their post-
    rewrite value is implementation-defined" rule. Pin #1
    is then UPDATED ATOMICALLY with the kernel change AND
    pin #5 (consensus_input || casefile cascade) MUST
    continue to pass — independently verifying that no
    downstream stage at D64 actually consumed the cold bytes.
  - Alternative WITHOUT panel approval: zero-initialize
    mask[1..31] in the workspace buffer at allocation time
    (one-time cost; preserves pin #1 byte-identical) AND
    skip the per-dispatch write. Adds ~1 MB allocation-time
    work but keeps pin #1 untouched. RECOMMENDED for first-
    pass safety.

Risk mitigations:
  - Pin #2 (compact-pack arena): unchanged — Phase 3 of
    detector_motif_fused still writes the 18-byte compact
    pack from registers.
  - Pin #3 (TreeSha256V1 root) + Pin #4 (CompactDensorDigestV1
    root): unchanged — both digests consume the compact-pack
    arena bytes (18 B per cell × n_cells), NOT the wide arena.
  - Pin #5 (consensus_input || casefile cascade): unchanged —
    consensus_axis5_fused reads only mask[0] at D64 via
    project_d64_to_u16; mask[1..31] cold bytes are not read.

D128/D205 dispatcher impact: NONE. Those dispatchers use the
legacy unfused 2-kernel pair (detector_motif_kernel_wide_d64 +
detector_wide_digest_pack_kernel_v1) which still writes the
full 264 B per cell. The conditional-write skip is D64 _timed
only.

Projected post-S-PERF.15.d local win:
  detector_motif_fused per-call wall: 2.48 ms → 1.4-1.8 ms
    (estimated -30 % to -45 %; bench-band-noisy)
  L2 throughput %: 92.3 % → 50-60 % (bucket shift OCC or DRAM)
  System-level bench: marginal at median (the saved ~0.7-1 ms
    is ~3-5 % of the 25-30 ms host wall; per-kernel ncu is
    the verdict, bench is context)

Honest expectation (per the S-PERF.15.c pattern): per-kernel
ncu shows clean 1.4-1.8× local win; system-level bench BW
delta within thermal noise band. Bench is the noise filter;
ncu is the verdict.

------------------------------------------------------------------------
 Likely Step 1 directions (HISTORICAL — superseded by byte-counter verdict)
------------------------------------------------------------------------

The field-audit suggests three plausible Step 1 directions. The
focused ncu byte-counter trace (Step 0d below) confirms or
refutes which one is best.

  Direction A — D64 conditional-write (highest payoff, highest
  contract risk):
    Skip mask[1..31] writes entirely on the D64 _timed path.
    Cuts write traffic 264 B → 16 B per cell (~277 MB → ~17 MB,
    16× write reduction).
    RISK: wide arena diverges from D128/D205 expected layout at
    mask[1..31] positions. Mitigation: harness pin #1
    (DETECTOR_CELLWIDE_ARENA_SHA256) detects this; if the panel
    accepts the divergence under a "D64 path defines its own
    write contract" rule, pin #1 is updated atomically with the
    kernel change AND pin #5 (cascade) independently verifies
    the digest + casefile paths are unchanged.
    PRESERVES: D128/D205 legacy unfused 2-kernel pair continues
    to write the full 264 B; the wide arena layout at D128/D205
    is untouched.

  Direction B — SoA sidecar (medium payoff, low contract risk):
    Write a 16-B D64-only compact cell (entity_id + window_idx +
    mask[0]) side-by-side with the full 264-B wide arena. D64
    consumers (consensus + candidate_pack) read the sidecar (16 B
    per cell instead of 264 B). Full wide arena still updated
    byte-identically (no write savings; but read footprint drops
    on downstream consumers).
    Reduces L2 read pressure on consensus by ~16×.
    PRESERVES: all 5 Step 0 pins byte-identical by construction
    (wide arena bytes unchanged; sidecar is additive, not a
    replacement).
    Cost: 1 new workspace buffer (1 048 576 × 16 B = 16 MB at
    canonical; trivially small).

  Direction C — Hybrid (highest payoff, highest design risk):
    Conditional-write the slim form to the sidecar AND skip
    mask[1..31] writes on the wide arena's D64 path; rebuild
    cold mask bytes lazily only if a D128/D205-mode consumer
    runs. Combines A's write reduction with B's read reduction.
    Most invasive; requires explicit lazy-rebuild for D128/D205
    compatibility.

The focused ncu run (Step 0d) measures whether the actual L2
pressure is on the write or the read side. If the
`l1tex__t_bytes_pipe_lsu_mem_global_op_st.sum` metric dominates
→ Direction A or C wins. If `_op_ld.sum` dominates → Direction B
wins. If both are large → Direction C is the panel-suggested
ceiling.

Interpretation rules (panel-locked):

    Specifically, sectors_ST / sectors_LD > 5 strongly favors A/C.

    Either the temporal-locality loop is exposing more read
    traffic than expected, or compiler is over-prefetching.
    Direction B (sidecar) targets the read side.
