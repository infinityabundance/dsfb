S-PERF.11 --- measured digest-lane compaction (summary)
========================================================

Campaign identity (panel-locked core sentence, verbatim)
--------------------------------------------------------

  S-PERF.11 performs the first measured digest-lane
  rewrite above the S-PERF.10 preservation contract. It
  reduces digest_total_us from 11,895 to 8,556 while
  preserving byte-identical TreeSha256V1 roots and R.12b
  episode counts.

Panel-locked report wording (verbatim --- mirrored across
README + paper + lib.rs + this receipt)
----------------------------------------

  S-PERF.11 records a measured digest-lane compaction
  improvement on RTX 4080 SUPER / CUDA 13.2. The four
  TreeSha256V1 digest roots remain byte-identical, and
  R.12b episode counts remain 13 / 89 / 1917. The
  measured digest total falls from 11,895 us to 8,556
  us, a 1.39x digest-speedup, while measured CUDA
  pipeline bandwidth rises from 13.33 GB/s to 16.38
  GB/s, a +22.9% improvement. This is an admissible
  measured improvement, not a memory-bandwidth
  saturation claim.

Panel-locked one-line verdict (verbatim)
----------------------------------------

  S-PERF.10 locked the digest preservation law;
  S-PERF.11 performs the first measured digest-lane
  rewrite and moves the scoreboard from 13.33 to 16.38
  GB/s without digest-root or episode-count drift.

What this DOES
--------------

  - Swaps the D64 tree-digest leaf launch from
    `tree_digest_leaf_kernel` (one chunk per block) to
    `tree_digest_leaf_kernel_v2` (32 chunks per block,
    one chunk per thread within a warp) WITHOUT changing
    the per-chunk SHA-256 input bytes. Per-chunk leaf
    digests byte-identical -> per-stage TreeSha256V1
    roots byte-identical -> S-PERF.10's
    `same_mode_digest_root_law` satisfied by
    construction.
  - Parses the four `tree_digest` rows + wide bandwidth
    + episode pin from
    reports/d64_stage_timing_256x4096_K1_post_s_perf_11.txt.
  - Anchors pre-rewrite stage timings + bandwidth as
    panel-locked constants from S-PERF.6 / S-PERF.10.
  - Pins the four pre + four post TreeSha256V1 root
    digests as panel-locked `[u8; 32]` constants in the
    receipt (mirroring the kernel-side
    `s_perf_11_pre_rewrite_root_capture` safety harness)
    and emits a per-stage `byte_identical` flag.
  - Binds measurement + root-equivalence + bandwidth
    pre/post + delta + saturation flag + four upstream
    anchor hashes (S-PERF.6 + S-PERF.7 + S-PERF.8.1 +
    S-PERF.10) + three R.12b episode pins into a single
    hashable receipt.

What this DOES NOT do
---------------------

  - Does NOT claim memory-bandwidth saturation (228 bp
    < 8000 bp threshold; saturation_admitted = false).
  - Does NOT change digest mode (TreeSha256V1 unchanged).
  - Does NOT mutate the S-PERF.6 / S-PERF.7 / S-PERF.8
    audit content or any prior hash anchor (the
    rebaselined S-PERF.10 contract + plan hashes are a
    panel-acknowledged wording-clarification schema
    upgrade landed in the same atomic commit; not an
    audit-content change).
  - Does NOT rebaseline the pinned R.12b D64 saturation
    reports (13 / 89 / 1917 byte-stable).
  - Does NOT alter SEED.len() (stays 54).
  - Does NOT run CUDA from inside the corpus crate
    (measurement is captured by `dsfb-gpu-debug-cuda`'s
    bench harness; this receipt parses the pinned post
    file).
