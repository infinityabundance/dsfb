S-PERF.3 PublicDataSaturationBundleV1 — Summary Receipt
========================================================

Panel verdict: post-S-PERF.2 panel directive (2026-05-17).
Sealed under the 10-step per-section discipline ritual.

Commit identity (panel-locked):

    S-PERF.3 defines the byte-pinned public artifact bundle
    used for future Layer-A saturation measurements. It
    does not claim saturation, does not benchmark
    throughput, and does not change kernels. It creates the
    reproducible public-data workload surface that
    S-PERF.4 / S-PERF.5 will measure.

Panel-locked verdict (verbatim):

    S-PERF.2 isolated the evidence-factory path; S-PERF.3
    gives that path a reproducible public workload to run
    on.

Core rule:

    No saturation benchmark without a byte-pinned public-
    data bundle. No dataset claim without source, license /
    access status, hash policy, and fixed materialization
    recipe.

Court-delta posture
----------------------------------------------------------------

S-PERF.3 ships ONLY the bundle schema + materialization
policy + verifier + builder + panel-locked baseline of five
citation-only manifests covering the five panel-named
dataset classes + renderers.

  - PublicArtifactManifestV1
    Per-dataset manifest declaring identity (dataset_id,
    display_name), classification (dataset_class,
    layer_a_role_mapping), access posture (access_note,
    license_or_access_status, usage_mode), hash policy
    (hash_policy_kind, per_artifact_sha256_count,
    source_archive_sha256), synthetic flag, and
    materialization recipe.

  - DatasetMaterializationPolicyV1
    Panel-locked 8-line policy doctrine pinned by its own
    dataset_materialization_policy_hash_v1.

  - PublicDataSaturationBundleV1
    Top-level wrapper binding all manifests (sorted
    ascending by dataset_id) + the policy + the bundle
    identity under a single META-hash.

----------------------------------------------------------------

  defects4j_v2         SoftwareDefectTable        MitLicense       (GitHub)

  nasa_cmapss_v1       IndustrialPublicFixture    PublicDomain     (NASA PCoE)

All baseline manifests are usage_mode=CitationOnly with
populated recipe (source_url_or_doi + local_path_template +
materialization_steps + deterministic_postprocess=true +
requires_live_remote_fetch=false). Each has
hash_policy_kind populated (Sha256PerFileManifest for the
4 GitHub datasets; Sha256OfSourceArchive for NASA C-MAPSS)
but per_artifact_sha256_count=0 and source_archive_sha256=
zero because the bytes are not yet materialised. Later
S-PERF.* commits flip usage_mode to MeasuredFixture and
populate the hash material.

All baseline manifests are is_synthetic=false (real public
data, not synthetic generators).

Eight panel-required load-bearing negatives
----------------------------------------------------------------

  1. s_perf_3_rejects_dataset_without_source_or_access_note
       — manifest with empty source_url_or_doi OR empty
         access_note.
  2. s_perf_3_rejects_artifact_without_hash_policy
       — manifest with HashPolicyKind::Unknown.
  3. s_perf_3_rejects_bundle_with_synthetic_only_data
       — bundle with zero manifests OR every manifest
         is_synthetic=true.
  4. s_perf_3_rejects_dataset_without_materialization_recipe
       — recipe missing local_path_template, missing
         materialization_steps, or MeasuredFixture with
         expected_bytes_after_materialization=0.
  5. s_perf_3_rejects_license_or_access_status_missing
       — LicenseOrAccessStatus::UnknownLicense.
  6. s_perf_3_rejects_unpinned_download_or_live_remote_dependency
       — recipe.requires_live_remote_fetch=true.
  7. s_perf_3_rejects_dataset_role_without_layer_a_mapping
       — LayerARoleMapping::Unmapped.
  8. s_perf_3_rejects_benchmark_claim_inside_bundle_definition
       — case-insensitive scanner over 12 forbidden
         substrings (achieves saturation / saturates the
         bandwidth / saturates peak / % of peak / percent of
         peak / outperforms / beats the baseline / world
         record / fastest gpu / production-ready performance
         / petaflops / memory-bandwidth saturation).

Panel-locked non-claims
----------------------------------------------------------------

S-PERF.3 does NOT:

  - claim that DSFB-GPU has saturated memory bandwidth (that
    is a separate S-PERF.4 / S-PERF.5 commit gated on the
    device-resident pipeline running on real hardware);
  - benchmark throughput;
  - emit any timing receipt;
  - change any CUDA kernel;
  - change any court decision (S1.3a / FF.2 / FF.3 / S1.3d
    / S1.3e / S1.3f / S1.3g);
  - mutate any upstream hash anchor;
  - alter SEED.len() (stays at 54);
  - emit detector outputs, witness records, fusion
    tensors, candidate intervals, or episodes;
  - decide contraindications or challenges;
  - modify the registry crate;
  - download or fetch any dataset bytes (the baseline ships
    citation-only manifests; live-remote fetches are
    forbidden by panel-required negative #6).

S-PERF.3 gives the Layer-A path a reproducible public
workload. The first measurement against this workload is
a later S-PERF.* commit.
