 Panel-locked one-line verdict (verbatim)
----------------------------------------------------------------

  The next lever is launch-geometry repair for occupancy-bound
  per-entity-serial kernels. It is not digest fusion first.

----------------------------------------------------------------
 Why this overrides the prior S-PERF.14 default
----------------------------------------------------------------

The S-PERF.13 plan + memory carried an earlier-default
S-PERF.14 lever of "fuse the 4 compact_densor digest stages".
That suggestion was based on the LOGICAL bench metric
`wide bytes/sec` (264 B/cell x cells/sec), which is the
nominal evidence-write footprint, NOT physical DRAM / L2 /
SM / PCIe traffic.

ROOF measured the actual fabric distribution. The dominant
actionable bucket is OCCUPANCY-BOUND launch geometry: five
kernels run at 2-6% achieved occupancy because their grids
expose only ~8 blocks to an 80-SM RTX 4080 SUPER. The single
largest single-kernel wall is drift_slew_sign_kernel at 1.6 ms
@ 2.1% occupancy. The compact_densor_root_kernel is also
structurally underfilled at 1 thread per block (1.2 ms wall @
2.1% occupancy).

Total occupancy-bound wall: ~4.1 ms (>50% of the
post-S-PERF.13 device wall). Total compact_densor digest
stages: ~3.2 ms (43%). Fixing launch geometry attacks the
larger slice first; the same fix may incidentally help
compact_densor_root.

 S-PERF.14 implementation direction (panel-locked)
----------------------------------------------------------------

  1. Fix drift_slew_sign_kernel first.
  2. Expand grid geometry from per-entity serial shape to
     tiled cell/window work.
  3. Preserve deterministic indexed output slots.
  4. No completion-order merge.
  5. Re-run Nsight after the launch-geometry fix.
  6. Only then revisit digest fusion if it remains dominant.
