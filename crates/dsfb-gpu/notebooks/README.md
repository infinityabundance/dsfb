# DSFB-GPU — Public S-REAL Replay Notebook (COLAB.S-REAL.1)

`dsfb_gpu_debug_colab.ipynb` is the **public replay surface** for the
20-dataset S-REAL audit gauntlet sealed at S-REAL.3.1.1 (`3fdf42f`).
It rebuilds the CUDA path from source on a free Colab GPU runtime,
re-runs `s-real-audit --dataset all` on the plan-locked vendored
fixtures, and produces a downloadable ZIP bundle the operator hands
to reviewers.

This notebook **replaces** the legacy v0 synthetic-fixture demo
(generate-fixture → run-cpu → run-gpu → compare). The new flow is
audit-gauntlet-centric, not toy-fixture-centric. If you are looking
for the historical v0 notebook, see the commit chain history.

## What the notebook proves (plan-locked classification)

Each run produces an explicit **A–F verdict block**:

  - **A — Build success**: `cargo build --release --features cuda`
    completes.
  - **B — Dataset SHA verification success**: every audit-required
    fixture matches the SHA-256 pin in `data/fixtures/MANIFEST.toml`.
  - **C — Audit run success**: `s-real-audit --dataset all` emits
    20 × 9 = 180 atomic artifacts.
  - **D — Per-run replay success**: every dataset's two within-run
    dispatches produce byte-identical casefile + episodes (the
    audit driver's own replay-verification gate).
  - **E — Bundle integrity success**: the 5-test
    `s_real_3_bundle_integrity` suite passes (the 60-row chain
    matches Colab-generated bytes).
  - **F — Cross-hardware byte-identity success**: this run's
    artifact bytes match the committed dev-machine seal byte-for-
    byte. E and F coincide for the 60 chain-pinned artifacts.

A–E PASS with F DIVERGENT is still a valuable finding — it documents
a portability boundary at the exact diverging artifact path. The
notebook reports it honestly; divergence is a finding, not a crash.

## Plan-locked honest framing

> The notebook attempts cross-hardware replay on Colab T4 / A100 /
> L4. If the emitted artifacts match the committed S-REAL bundle,
> this is evidence of cross-hardware determinism for that
> environment. If they diverge, the notebook reports the exact
> differing artifact and preserves the result as an honest
> portability finding.

## Producing the source tarball

From the dev-machine repo root:

```
bash scripts/pack_for_colab.sh
```

The script writes a slim ~18 MB tarball at
`target/colab/dsfb-gpu.tar.gz`. The tarball includes:

- the full Rust + CUDA source tree so Colab can rebuild from scratch
- `data/fixtures/*.tsv` — the 20 SHA-pinned audit input TSVs
- `data/fixtures/MANIFEST.toml` — the pin table the notebook
  verifies (B-gate)
- `notebooks/` (for self-reference) + `scripts/` (including the
  new ZIP producer)
- `reports/` carrying the sealed S-REAL.3.1.1 bundle so the
  cross-hardware comparison (E + F gates) has a target to compare
  against

The tarball **excludes** by construction:

- `target/`, `.git/` — build artifacts and VCS metadata
- `data/upstream/`, `data/CMAPSSData.zip` — upstream reconstruction
  archives (~28 MB; the audit doesn't need them)
- `data/fixtures/*x1024.tsv` — the 10 large saturation-class TSVs
  (~90 MB; the audit doesn't run them and the saturation sweep is
  dev-machine hardware-anchored)

## Audit / saturation surface split (plan-locked S-REAL.3.1.2)

The audit driver maintains **two separate dataset identity tables**
inside `crates/dsfb-gpu-debug-demo/src/cli/s_real_audit.rs`:

- **`AUDIT_DATASETS` (20 entries)** — the sealed S-REAL audit
  gauntlet datasets. Every entry's `tier_dir` is `s_real_1`,
  `s_real_2`, or `s_real_3` mirroring the on-disk sealed bundle
  layout at `reports/s_real_3/bundle_manifest.toml`. `s-real-audit
  --dataset all` enumerates **only this table**.
- **`SATURATION_FIXTURES` (10 entries)** — the large saturation-
  class real-data fixtures (RadioML, DeepBeam, RadioML-Gold,
  POWDER, ORACLE, Deepsense6G, IMDb tarball, IMDb DuckDB, Snowset,
  SQLShare). Every entry's `tier_dir` is `s_real_saturation`.
  These fixtures are **NEVER selected by `--dataset all`**; they
  dispatch only via explicit single-id audit calls
  (e.g. `s-real-audit --dataset radioml_2018_snr30_large`) and via
  `scripts/s_real_saturation_sweep.sh`. Their 1 M-cell TSVs are the
  ~90 MB the slim tarball deliberately excludes.

Why the split matters for the Colab path: before S-REAL.3.1.2 the
driver carried a single `DATASETS` constant of 30 entries, and
`s-real-audit --dataset all` would silently dispatch the 10
saturation witnesses whose TSVs the slim tarball intentionally
omits. The split makes the boundary load-bearing — the
notebook's `--dataset all` command can never accidentally try to
read a missing TSV, and five unit tests
(`audit_all_dataset_count_is_20`,
`saturation_fixture_count_is_10`,
`audit_all_excludes_large_saturation_fixtures`,
`audit_dataset_table_no_duplicate_ids`,
`audit_dataset_tier_dir_matches_bundle_manifest`) pin the
invariants so a future regression fails CI before reaching the
public-replay path.

The notebook also runs a **PENDING-guard cell** before
`files.download()` that asserts no `<PENDING>` markers remain in
any text artifact inside the ZIP — the packer
(`scripts/package_s_real_colab_outputs.sh`) emits the
`colab_run_receipt.md` skeleton with `<PENDING>` placeholders for
the A-F gates, and the notebook substitutes the populated body
from the §7 verdict before inviting the operator to download. The
PENDING-guard prevents a regression where the substitution gets
missed and the operator receives a ZIP with empty A-F fields.

## Running the notebook

1. Open `dsfb_gpu_debug_colab.ipynb` in Colab.
2. Set **Runtime → Change runtime type → GPU** (T4 / A100 / L4 all
   work; CPU-only is **not supported** — `s-real-audit` requires
   the CUDA path).
3. **Run all cells** top-to-bottom (Runtime → Run all).
4. The §1 upload cell prompts you to select the tarball produced
   by `pack_for_colab.sh`.
5. The final cell triggers a browser download of
   `dsfb_gpu_audit_bundle.zip` (~1.2 MB containing all 180 audit
   artifacts + the sealed bundle receipts + INDEX.md + the
   `colab_run_receipt.md` provenance).

Expected end-to-end runtime: ~3–5 minutes on T4.

## ZIP producer

The notebook calls `scripts/package_s_real_colab_outputs.sh` to
assemble the bundle. Operators can run the same script on the dev
machine to refresh a reference bundle locally:

```
bash scripts/package_s_real_colab_outputs.sh
# → reports/s_real_colab_outputs.zip
bash scripts/package_s_real_colab_outputs.sh --out /tmp/bundle.zip
# → /tmp/bundle.zip
```

The script refuses to build the ZIP if any of the three tier
directories (`reports/s_real_1/`, `s_real_2/`, `s_real_3/`) is
missing — partial bundles would be misleading.

## Plan-locked non-claims

These appear verbatim in the notebook §8, the bundle's
`colab_run_receipt.md`, and any communication built on top of this
artifact:

- COLAB.S-REAL.1 does NOT add new datasets, kernels, or hashes.
- COLAB.S-REAL.1 does NOT change S-REAL.3.1.1's claims; it only
  makes them reproducible on third-party hardware.
- COLAB.S-REAL.1 does NOT claim Colab-runtime saturation or any
  new performance result — the saturation sweep is the dev-machine
  hardware-anchored measurement.
- COLAB.S-REAL.1 does NOT claim cross-hardware byte-identity until
  the F-gate has actually been run; the notebook reports what it
  observed honestly.
- COLAB.S-REAL.1 does NOT modify the audit's algorithm, fixtures,
  contracts, or hash chain.
- The downloaded bundle does NOT claim Zenodo deposit or DOI
  assignment on its own; those are separate publication acts.
- The notebook is offered as a **reproducibility tool**, NOT as a
  benchmarking platform — Colab thermal variance makes any per-run
  GB/s number a courtesy snapshot, not a measurement claim.
- Colab T4 / A100 / L4 is NOT RTX 4080 SUPER + CUDA 13.2 (the
  dev-machine hardware anchor); timing values in
  `perf_profile.txt` are RUNTIME-DEPENDENT and NOT comparable to
  the anchor.
